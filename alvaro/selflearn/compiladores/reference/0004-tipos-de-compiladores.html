Traductores y tipos de compiladores

Decide cualquier pregunta con dos ejes: qué produce y cuándo / para dónde compila.

Eje 1 · Qué produce

TraductorSalida¿Tú ejecutas algo después?Ejemplo
Compiladorcódigo máquina / objetoSíGCC, Clang, javac (bytecode)
Intérpretenada; ejecuta el programaNoCPython, un intérprete de Lisp
Transpiladorcódigo fuente de alto nivelSí (compilas el resultado)TypeScript→JS, Babel, Sass
Descompiladorcódigo de más alto nivelSí (revisas/editas)JAD, Ghidra
La trampa central

Transpilador ≠ compilador a máquina. Sale código fuente de alto nivel. Si el enunciado dice «genera código máquina», es falso para un transpilador.

Eje 2 · Cuándo y para dónde compila

TipoRegla de una frase
CruzadoCorre aquí, genera código para otra plataforma.
NativoCorre aquí, genera código para esta plataforma.
JITCompila durante la ejecución, por fragmentos. Parte de un intérprete/runtime.
AOTCompila todo antes de ejecutar. (Opuesto al JIT.)
IncrementalRecompila solo lo que cambió.
Una pasadaLee el fuente una sola vez.
Varias pasadasRelee el fuente varias veces antes de generar.
OptimizadorMejora eficiencia sin cambiar el significado.
De arranqueSirve para construir una versión mejor del compilador.
Compilador-compiladorHerramienta que genera compiladores (lex/yacc, ANTLR).

La taxonomía no es excluyente: un compilador puede ser cruzado, optimizador y de varias pasadas al mismo tiempo.

Árbol de decisión

  1. ¿Qué sale? ¿Máquina? → compilador. ¿Fuente de alto nivel? → transpilador. ¿Nada, ejecuta? → intérprete.
  2. Es compilador. ¿Para qué plataforma genera? ¿Otra? → cruzado. ¿La misma? → nativo.
  3. ¿Cuándo compila? ¿Durante la ejecución? → JIT. ¿Antes, todo? → AOT.
  4. ¿Cuánto trabajo repite? ¿Solo lo cambiado? → incremental. ¿Todo? → recompilación completa.

Trampas que fallan en el examen

  • «JIT compila todo antes de ejecutar» → F. Eso es AOT.
  • «Un intérprete nunca compila» → F. CPython compila a bytecode.
  • «Un transpilador genera código máquina» → F. Genera código fuente.
  • «Compilador cruzado significa que cruza módulos» → F. Es otra plataforma.
  • «El optimizador puede cambiar lo que hace el programa» → F. Conserva el significado.
  • «Compilador e intérprete son mutuamente excluyentes» → F. Go es ambos; CPython interpreta y compila.

Conexiones con el resto del temario

  • El bytecode es código intermedio que ejecuta una máquina virtual (junto con un JIT en JVM/V8/CLR).
  • El compilador cruzado es posible gracias a que el back-end está separado y depende de la máquina.
  • El código intermedio es lo que permite reutilizar front-ends y back-ends entre plataformas.
