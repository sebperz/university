Glosario

El vocabulario canónico del curso. Si una lección y el glosario se contradicen, gana el glosario. Términos en inglés entre paréntesis cuando son el estándar.

Traductores

Compilador
Programa que traduce código de un lenguaje fuente a otro lenguaje destino (normalmente de alto nivel a bajo nivel: ensamblador, bytecode o código máquina) sin ejecutarlo. alias a evitar: traductor en general
Intérprete
Programa que toma el código fuente y lo ejecuta directamente, sin producir un ejecutable separado. Muchos intérpretes compilan internamente a bytecode (p. ej. CPython).
Transpilador
Compilador que traduce entre dos lenguajes de nivel similar y produce código fuente como salida, no código máquina. también: compilador fuente a fuente, transcompiler
Compilador cruzado (cross-compiler)
Compilador que se ejecuta en una plataforma pero genera código para una plataforma o arquitectura distinta.
Compilador JIT (just-in-time)
Compilador que traduce fragmentos de código a máquina durante la ejecución del programa, según se necesitan. No genera un ejecutable permanente por adelantado.
Compilador nativo
Compilador que genera código máquina para la misma arquitectura en la que se ejecuta.
Compilador incremental
Compilador que recompila solo las partes del programa que cambiaron, reutilizando el trabajo previo.
Compilador de una pasada / de varias pasadas
De una sola pasada: genera el código con una única lectura del fuente. De varias: necesita leerlo varias veces antes de producir el código.
Compilador de arranque (bootstrap compiler)
Compilador temporal que se usa para compilar una versión más definitiva o mejor optimizada del compilador de un lenguaje.

Partes y fases

Front-end
Parte que analiza el código fuente y depende del lenguaje fuente: análisis léxico, sintáctico y semántico. en español: analizador
Back-end
Parte que sintetiza el código destino y depende de la arquitectura: generación de código. en español: generador
Análisis léxico (scanning, lexing)
Primera fase. Lee el flujo de caracteres y lo agrupa en tokens; descarta espacios y comentarios. Error típico: símbolo mal formado.
Análisis sintáctico (parsing)
Segunda fase. Agrupa los tokens según la gramática y construye un árbol. Error típico: estructura inválida, paréntesis faltante.
Análisis semántico
Tercera fase. Comprueba el significado: compatibilidad de tipos, declaración de identificadores, ámbitos. Error típico: tipos incompatibles.
Optimización
Fase que reescribe el código intermedio para hacerlo más eficiente conservando su significado.
Generación de código (code gen)
Fase final del back-end: convierte la representación intermedia en código máquina o ensamblador para la arquitectura destino.
Fase de análisis / fase de síntesis
Las dos grandes tareas: análisis = comprobar y entender el fuente; síntesis = generar el código objeto.

Estructuras de datos

Token
Unidad mínima con significado que produce el analizador léxico. Consta de un nombre de categoría y, opcionalmente, un valor. Ej.: (identificador, "x").
Lexema
La secuencia concreta de caracteres del código fuente que corresponde a un token. En x = 2;, los lexemas son x, =, 2, ;.
Patrón
La regla que describe cómo se reconoce un lexema de cierta categoría (a menudo una expresión regular). Ej.: identificador = [a-zA-Z_][a-zA-Z_0-9]*.
Maximal munch (regla del emparejamiento más largo)
Criterio del lexer: siempre toma la cadena más larga posible que forme un token válido.
Árbol de sintaxis abstracta (AST)
Representación en árbol del programa que captura su estructura esencial, sin detalles de la sintaxis concreta. Lo construye el parser.
Árbol de análisis sintáctico (parse tree)
Árbol que refleja fielmente las reglas de la gramática aplicadas, con más detalle que el AST.
Tabla de símbolos
Estructura que guarda información de los identificadores (nombre, tipo, dirección, ámbito). La usan casi todas las fases, no solo una.
Ámbito (scope)
Región del programa donde un nombre se refiere a una declaración concreta. Clave para la resolución de nombres.
Código intermedio (IR)
Representación interna del programa, independiente del lenguaje fuente y de la máquina destino. Facilita la optimización y la portabilidad. Ej.: código de tres direcciones.
Bytecode
Código intermedio para una máquina virtual, con instrucciones normalmente de un byte, ejecutado por un intérprete de bytecode.
Máquina virtual (VM)
Programa que emula una máquina hipotética para ejecutar bytecode en tiempo de ejecución.
