Lección 01 · Compiladores Objetivo: ubicar cada fase

El mapa del compilador

Un compilador no es una caja negra: es una cadena de fases, y cada fase tiene un trabajo y un tipo de error que le pertenece. Si dominas esto, ya resolviste varias preguntas del examen.

La idea de hoy

Un compilador traduce código de un lenguaje a otro pasando por representaciones cada vez más cercanas al significado, y luego cada vez más cercanas a la máquina. Primero entiende (análisis), después produce (síntesis).

Visualízalo como subir y bajar una montaña: subes desde el texto crudo hasta el significado, y bajas desde el significado hasta el código ejecutable. (Nystrom, Crafting Interpreters, cap. 2)

Las dos mitades (y algo en el medio)

El recorrido se suele dividir así, y esta división es una pregunta clásica de examen (Wikipedia ES: Compilador):

ParteQué haceFases

Middle-end

Back-end

Trampa de examen

El análisis léxico NO verifica la gramática. Solo convierte caracteres en tokens. Decir que verifica la estructura gramatical es falso: eso es el análisis sintáctico.

Cada fase, en una línea

  1. Análisis léxico (scanner/lexer): lee el texto de izquierda a derecha y lo agrupa en tokens. Descarta espacios y comentarios. Errores: un carácter o símbolo que no forma ningún token válido.
  2. Análisis sintáctico (parser): agrupa los tokens según la gramática y construye un árbol. Errores: estructura incorrecta, paréntesis o llaves sin cerrar, falta un ;.
  3. Análisis semántico: comprueba el significado — que los tipos sean compatibles, que las variables existan, que el ámbito sea correcto. Errores: sumar un número con un texto, usar una variable no declarada.
  4. Código intermedio: representación neutra (p. ej. código de tres direcciones) que separa la lógica del programa del hardware concreto.
  5. Optimización: reescribe el código intermedio para que sea más eficiente, sin cambiar lo que hace.
  6. Generación de código: traduce a código máquina o ensamblador para la arquitectura destino.
