# Mission: Compilers

## Why
I'm taking a university compilers course (in Spanish) and want to pass it *and* genuinely understand how compilers work — not cram. I learn best by building, so I'll construct a working interpreter for a small language in Python, one compiler phase at a time.

## Success looks like
- Pass the course activities and exam.
- A working Python interpreter for a small language, built phase by phase: lexer → parser → AST → evaluator.
- Can explain each phase in my own words (lexing, parsing, semantic analysis) and tie it to the course's Spanish terminology.
- Can solve course exercises on regular expressions, DFAs, grammars, and ambiguity from memory.
- My vocabulary and mental model are solid enough that the course's formal material (Dragon Book style) reads as familiar rather than opaque.

## Constraints
- Complete beginner to compilers (no prior lexer/parser experience).
- University semester timeline — lessons must be short and project-driven.
- Course materials are in Spanish; my activities reference the Dragon Book (Aho, Lam, Sethi & Ullman).
- Project language: Python (chosen for minimal friction).
- I want to build the project as I learn — not a theory-only path.

## Out of scope
- Compiler optimizations (register allocation, instruction scheduling, SSA) — only if/when the course requires them.
- Writing the compiler in C/Rust/Go — possibly a future side-quest after the course.
- Building a second, bigger language for now.
