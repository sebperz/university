Glossary of Compiler Terms

The working vocabulary of this course. Spanish course terms are shown in italics.

Compilers are described with a very specific vocabulary. When you can name the parts precisely, the formal material (grammars, automata, parsing theory) stops being intimidating and becomes a set of definitions you already speak. This page is the glossary every lesson adheres to — if a word is used in a lesson, its definition is here.

What the compiler is

TermDefinition
Compiler A program that translates a source program written in one language into an equivalent program in another language (usually machine or byte code). Compilador
Interpreter A program that executes a source program directly, without translating it to another language first. Our project builds an interpreter for its first phase. Intérprete
Source program The text the programmer writes. The input to the whole pipeline. Programa fuente
Target program The output of a compiler: machine code, bytecode, or another language. Programa objeto
Front end The phases that depend only on the source language: lexing, parsing, semantic analysis. Language-independent of the target. Fase frontal
Back end The phases that depend on the target: code generation and optimization. Fase final

Phase 1 — Lexical analysis

TermDefinition
Lexical analysis The phase that reads the source text and groups characters into tokens. It is the "spellchecker" of the compiler. Análisis léxico
Scanner / lexer / tokenizer The component that performs lexical analysis. Reads characters one at a time. Analizador léxico
Token A categorized unit of meaning: a keyword, identifier, number, operator, or punctuation. Tokens carry a type and often a value. Componente léxico / token
Lexeme The actual characters in the source that a token was made from. "The lexeme is x, the token type is IDENTIFIER." Lexema
Regular expression A compact notation describing a set of strings. Used to specify which lexemes each token type accepts. Expresión regular
DFA (deterministic finite automaton) A state machine with exactly one transition per input symbol per state. Used to recognize tokens efficiently; every regex can be converted to a DFA. Autómata finito determinista (AFD)
NFA (nondeterministic finite automaton) A state machine where a symbol may trigger zero, one, or many transitions. Easier to build from a regex; converted to a DFA for execution. Autómata finito no determinista (AFN)

Phase 2 — Syntax analysis

TermDefinition
Syntax analysis / parsing The phase that checks whether the sequence of tokens matches the rules of the grammar. It answers: "is this the right shape?" It does not care what names mean. Análisis sintáctico
Parser The component that performs syntax analysis, building a parse tree (or detecting a syntax error). Analizador sintáctico
Grammar A formal set of rules (productions) describing the valid structure of programs. Gramática
Production / rule A single grammar rule of the form head → body: "this non-terminal can be replaced by this sequence of symbols." Producción
Terminal A symbol that cannot be expanded further — it is a concrete token (num, +, (). Símbolo terminal
Non-terminal A symbol that must be expanded by some production (written as a name like S, Expr). No terminal
Start symbol The non-terminal from which every derivation begins; the root of every parse tree. Símbolo inicial
Derivation A sequence of production applications that turns the start symbol into a concrete string of terminals. Derivación
Parse tree A tree recording how a string was derived from the grammar: root = start symbol, leaves = terminals. Árbol de derivación / sintáctico
Ambiguity A grammar is ambiguous if some string has two different parse trees. Bad: the compiler cannot choose a unique meaning. Ambigüedad
Recursive descent A hand-written parsing technique: one function per non-terminal, calling each other recursively. The style we use in our project. Descenso recursivo
AST (abstract syntax tree) A condensed version of the parse tree that keeps only the structure needed for later phases — drops punctuation like parentheses. Árbol de sintaxis abstracta

Phase 3 — Semantic analysis

TermDefinition
Semantic analysis The phase that checks the meaning: types, that names are declared, that operations are legal. Shape can be right while meaning is wrong. Análisis semántico
Symbol table The data structure mapping declared names to their attributes (type, scope, etc.). The semantic analyst's memory. Tabla de símbolos
Type checking Verifying that operations are applied to compatible types (i32 = "hola" fails here). Comprobación de tipos
Scope The region of a program in which a name is visible. Managing scope is a key symbol-table job. Ámbito

Phase 4 — Code generation

TermDefinition
Code generation The phase that emits the target program (machine code, bytecode, or another language) from the analyzed program. Generación de código
Optimization Rewriting the generated program to run faster or use less memory without changing its meaning. Out of scope for now. Optimización
Bytecode A compact, low-level instruction set executed by a virtual machine rather than hardware. Common for interpreted languages. Código de bytes
