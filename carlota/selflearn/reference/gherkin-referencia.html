Gherkin en español: sintaxis ejecutable

Todo lo que necesitas para escribir escenarios Dado-Cuando-Entonces que un motor de BDD pueda ejecutar.

Esqueleto de un archivo .feature en español

# language: es   ← SIEMPRE en la primera línea para keywords en español
Característica: Emparejamiento geoespacial de órdenes
  El motor asigna cada orden al repartidor más cercano sin condiciones de carrera.

  Antecedentes:            (Background: pasos comunes a todos los escenarios)
    Dado que el servicio de matching está operativo

  Escenario: Asignación sin competencia
    Dado que el repartidor "R-77" está libre en la zona centro
    Cuando llega la orden "O-1001" para recogida en la plaza mayor
    Entonces la orden queda asignada a "R-77" en ≤ 200 ms
      Y el repartidor recibe la notificación de asignación

Las 3 reglas de oro

Regla 1 · Dado = estado, no acción«Dado que el repartidor R-77 está libre» ✓ · «Dado que el usuario hace clic en asignar» ✗ (eso es un Cuando).
Regla 2 · Un solo CuandoEl Cuando es EL evento que estudias. Si necesitas dos eventos, son dos escenarios (o el segundo es un Dado/Y previo).
Regla 3 · Entonces = observableFowler y Cucumber coinciden: el Entonces verifica una salida del sistema (respuesta HTTP, notificación, mensaje en cola, métrica), no una fila escondida en la base de datos.

Esquema del escenario (mismo flujo, muchos valores)

Esquema del escenario: Degradación del proveedor de mapas
  Dado que el proveedor de rutas responde en <latencia_proveedor> ms
  Cuando llega una solicitud de ruta para la orden "<id_orden>"
  Entonces el sistema <comportamiento> en ≤ 300 ms

  Ejemplos:
    | latencia_proveedor | id_orden | comportamiento                  |
    | 50                 | O-2001   | calcula la ruta óptima          |
    | 400                | O-2002   | activa rutas cacheadas          |
    | timeout            | O-2003   | usa la última ruta conocida     |
