Referencia

Glosario

El vocabulario que usamos en todo el curso. Si una lección introduce una palabra nueva, aquí está su definición corta.

Fundamentos

Dominio
Nombre registrado que identifica un espacio en DNS, como example.com. No es lo mismo que el sitio web que apunta a él.Evita: página, host
DNS
Base de datos distribuida y jerárquica que responde consultas sobre nombres. Guarda direcciones, servidores de correo, políticas y textos de verificación.Evita: directorio, guía telefónica
Registro DNS
Entrada tipada dentro de DNS. El tipo define qué dato contiene: una IP (A), un servidor de correo (MX), un texto (TXT) o un nameserver (NS).Evita: fila, entrada
Subdominio
Nombre que cuelga de un dominio, como mail.example.com. Puede tener su propia configuración y su propia política DMARC.
Dominio organizacional
El dominio que alguien registró bajo un sufijo público. Para news.example.co.uk es example.co.uk. DMARC lo usa para comparar alineación relajada y para buscar políticas heredadas.
Lista de sufijos públicos (PSL)
Lista que distingue qué parte de un nombre se puede registrar. Sin ella, co.uk parecería un dominio organizacional.
RDAP
Protocolo de consulta de datos de registro que devuelve JSON. Sustituye a whois en la práctica y usa URL predecible.Evita: whois 2.0
Whois
Consulta de texto sobre el registro de un dominio o una IP. Sigue funcionando, pero muchos datos personales aparecen redactados.
Registro TXT
Registro DNS que contiene texto libre. Ahí viven SPF, DMARC y las verificaciones de servicios externos.
Registro MX
Registro que indica qué servidores reciben el correo de un dominio y con qué prioridad. Menor número, mayor preferencia.

Correo

SMTP
Protocolo que transporta correo entre servidores. No verifica por sí solo que el remitente controle el dominio que escribe.
From (RFC5322.From)
Cabecera que el usuario ve como remitente. Es el identificador central de DMARC y el que se falsifica en un spoofing exacto.Evita: remitente, autor
MAIL FROM
Remitente del sobre SMTP. Casi nunca se muestra al usuario. SPF autentica este dominio, no el From visible.
SPF
Registro TXT que enumera qué IPs pueden enviar correo para un dominio. Autentica el dominio del sobre, no el From.Evita: lista blanca de correo
DKIM
Firma criptográfica añadida al mensaje. Declara un dominio firmante en d= y permite verificar que el contenido no cambió en tránsito.Evita: cifrado de correo
Alineación
Condición de que el dominio autenticado por SPF o DKIM coincida con el dominio del From. Sin alineación, un pase de SPF o DKIM no sirve para DMARC.
DMARC
Política publicada en DNS que indica qué hacer con el correo que usa un dominio en el From y no pasa SPF o DKIM alineados. También define dónde enviar informes.Evita: antispam, firewall de correo
Política DMARC
Valor de p, sp o np: none, quarantine o reject. Expresa una preferencia; el receptor puede apartarse y reportarlo.
p
Política para el dominio del From. Si falta, se trata como none.
sp
Política para subdominios existentes. No aplica al dominio raíz.
np
Política para subdominios que no existen. Etiqueta nueva del RFC 9989. Si falta, se usa sp o p.
rua
Dirección que recibe informes agregados. Sin rua, el dominio no recibe reportes y opera a ciegas.
ruf
Dirección que recibe informes por mensaje fallido. Da más detalle que rua y expone más datos personales.
Informe agregado
Resumen periódico, normalmente XML comprimido, con IPs, dominios y resultados de autenticación. Definido en el RFC 9990.
Informe de fallo
Reporte de un mensaje concreto que falló. Puede incluir cabeceras y datos del mensaje. Definido en el RFC 9991.
Spoofing exacto
Uso no autorizado del dominio exacto en el From. Es lo que DMARC puede frenar. No cubre dominios parecidos ni nombres visibles falsos.
Dominio primo
Dominio visualmente parecido al legítimo, como tu-banco.co frente a tu-banco.com. DMARC no lo detiene.Evita: dominio falso, typosquatting (no siempre es lo mismo)

OSINT

OSINT
Inteligencia obtenida de fuentes públicas. En este curso significa datos accesibles sin credenciales ni explotación.Evita: hacking, espionaje
Reconocimiento pasivo
Consulta de fuentes y registros existentes sin enviar tráfico al objetivo. Quien consulta no aparece en los logs del objetivo, aunque el proveedor de la fuente sí ve la consulta.
Reconocimiento activo
Interacción directa con la infraestructura del objetivo: resolución DNS propia, peticiones HTTP, escaneo de puertos. Requiere autorización.
Banner
Respuesta inicial de un servicio que revela software, versión o configuración. Shodan y Censys indexan banners.
Fingerprinting
Identificación de la tecnología de un sitio o servidor a partir de cabeceras, cookies, rutas y comportamiento.Evita: huella digital
Metadatos
Datos dentro de un archivo que no se ven al abrirlo: autor, software, ruta, fechas, usuarios. FOCA y exiftool los extraen.
Certificate transparency
Registro público de certificados TLS emitidos. Sirve para descubrir subdominios que no aparecen en DNS ni en el sitio principal.
Cómo se mantiene

Un término entra aquí cuando puedes usarlo correctamente, no cuando lo leíste. Si una definición te parece incompleta, dímelo y la corregimos. Las definiciones de DMARC siguen el RFC 9989.
